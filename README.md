# Голосовой AI-рекрутер для первичного скрининга

Боль заказчика, дословно с разбора: «почти любое интервью у меня начинается с того, что я
пятнадцать-двадцать минут рассказываю о компании. А после этого кандидат может открыть рот, а
он двух слов связать не может». Плюс вторая половина: ответы на вопросы приходят перепиской,
и по ним не видно, **как** человек говорит — «я вижу ответы, но не слышу, насколько системно».

Поэтому у агента два равных блока. Первый — рассказать о компании и роли и ответить на вопросы
кандидата из базы знаний, в удобное кандидату время. Второй — задать вопросы по роли. На выходе
рекрутер получает заполненную карточку и может **отслушать** ключевые места.

Карточка отвечает не на вопрос «что кандидат сказал», а на вопрос **как он это сказал**:
отвечает ли он на заданный вопрос или уплывает в сторону; есть ли в его примере «ситуация → что
сделал сам → результат»; какой у него уровень английского и **на каких именно фразах** это
видно; говорит он свободно или зачитывает заранее подготовленный текст; и о чём он спросил сам.

Главное свойство: **каждое утверждение в карточке подкреплено цитатой из разговора, и цитата
кликабельна — по клику играет тот самый фрагмент записи**. Утверждение, под которое не нашлось
опоры в конкретной реплике, в карточку не попадает: оно выбрасывается кодом, а не остаётся на
совести модели. Решение по кандидату принимает человек — карточка показывает, на что смотреть.

## Демо

| Кто | Ссылка | Что там |
|---|---|---|
| Кандидат | `/interview` | Согласие → проверка микрофона → разговор → «спасибо» |
| Рекрутер | `/dashboard` | Список скринингов со статусами |
| Рекрутер | `/card/<id>` | Карточка: сводка, факты, о чём спросил сам, структурность, CEFR, манера речи |

Кандидатский флоу на английском, карточка и дашборд на русском, цитаты остаются на языке
разговора. В демо-сборке кандидату после интервью показывается ссылка на его же карточку —
в продакшене он её не видит (`NEXT_PUBLIC_DEMO_MODE`).

## Как это работает

```
КАНДИДАТ (EN)                                   РЕКРУТЕР (RU)
     │                                                │
     ▼                                                ▼
/  →  /interview                                 /dashboard → /card/[id]
     │                                                │
     │ 1. consent-экран (имя + согласие на запись)     │ карточка:
     │ 2. проверка микрофона                          │ • стоп-факты + цитаты
     │ 3. POST /api/session → id сессии, без ключей     │ • структурность
     │ 4. SDP через /api/realtime/call → OpenAI         │ • CEFR (или «мало данных»)
     │    дальше медиа идёт браузер ↔ OpenAI напрямую  │
     │                                                 │ • манера речи
     ├──► реплики + тайминги ──► POST /api/turns ──────┤ каждое утверждение →
     │    (каждые 4 сек, инкрементально)               │ цитата → клик → фрагмент
     │                                                 │
     ├──► аудио: mic + голос агента → MediaRecorder    │
     │    чанки ~15 сек ──► напрямую в Vercel Blob     │
     │                                                 │
     ▼ конец разговора: POST /api/turns { done: true } │
     │                                                 │
СЕРВЕР доводит до конца сам (клиента может уже не быть)│
     │                                                 │
     ├─ prepareAudio: склейка чанков → ремукс          │
     │   → перематываемый файл с длительностью          │
     │                                                 │
     └─ runAnalysis:                                   │
        ├─ шаг 0 (код): нейтральные метрики,           │
        │   порог достаточности речи                    │
        ├─ шаг 1 (LLM, strict JSON, параллельно):      │
        │   структурность │ CEFR │ манера │ факты │      │
        │   вопросы кандидата                            │
        ├─ шаг 2 (код): проверка цитат по транскрипту, │
        │   утверждения без опоры выбрасываются         │
        ▼                                              │
   Neon Postgres (sessions) ───────────────────────────┘
   Vercel Blob (чанки + перематываемая запись)
```

Три места, где решение неочевидно, и почему сделано так:

**В браузере нет никакого ключа — вообще.** Браузер отдаёт свой SDP-оффер нашему серверу,
сервер добавляет к нему конфиг разговора, идёт в OpenAI со своим постоянным ключом и возвращает
SDP-ответ. Дальше звук течёт напрямую браузер ↔ OpenAI, через нас не проходит. Это официальный
серверный вариант из документации Realtime, и он лучше эфемерного ключа по двум причинам:
конфиг сессии клиент подменить не может, и запрос к OpenAI уходит из региона развёртывания —
кандидат может сидеть там, где OpenAI не обслуживает по IP.

**Тайминги цитат берутся из серверных событий определения речи**, а не из клиентских часов:
`speech_started.audio_start_ms` и `speech_stopped.audio_end_ms` склеиваются с расшифровкой по
общему `item_id`. Файл записи начинается позже начала сессии, поэтому при старте записи
замеряется сдвиг между двумя шкалами — без него цитата играла бы не те слова, молча.

**Фрагмент цитаты играется через Web Audio, а не через `<audio>.currentTime`.** По стандарту
HTML браузер, не найдя запрошенную позицию в доступном диапазоне, **молча переходит на
ближайшую** и сообщает об успехе. На странице, которая существует ради доказательств, это
худший из возможных сбоев. Web Audio играет диапазон по семплам.

Анализ запускает сервер тем же запросом, которым клиент закрывает разговор. Кандидат может
закрыть вкладку сразу после «спасибо» — карточка всё равно построится.

## Локальный запуск

```bash
npm install
cp .env.example .env.local   # заполнить ключи
npm run db:init              # создать таблицу sessions
npm run dev
```

Переменные окружения перечислены в [.env.example](.env.example). Клиенты базы и OpenAI
создаются при первом обращении, а не при импорте, поэтому `npm run build` и `npm run test`
проходят без ключей — секреты нужны только для живого прогона.

```bash
npm run test        # 156 тестов: сборка реплик, валидация цитат, метрики, роуты, конфиг роли
npm run typecheck
npm run build
```

**Оговорка про географию:** OpenAI отвечает `403 unsupported_country_region_territory`, если
запрос приходит из неподдерживаемого региона. Запрос к OpenAI делает **сервер**, поэтому на
Vercel всё работает независимо от того, где сидит кандидат. А вот `npm run preflight` и
локальный `npm run dev` из закрытого региона потребуют VPN в **TUN-режиме**: `fetch` в Node
не читает `HTTPS_PROXY`, поэтому системного прокси недостаточно. Это ограничение разработки,
а не продукта.

**Оговорка про локальный прогон:** Vercel Blob не вызывает `onUploadCompleted` на localhost,
поэтому клиент регистрирует каждый чанк сам через `POST /api/audio/register` — этот путь
работает и локально, и на проде. Если запись всё же не собралась, карточка строится без
аудио: цитаты остаются текстовыми, а починить запись можно через `POST /api/audio/prepare`,
не переигрывая интервью.

## Чего этот инструмент не делает

Не оценивает акцент, темп речи, пол и возраст. Не считает паузу негативным сигналом сама по
себе — кандидат имеет право подумать. Не выводит эмоциональное состояние: в контексте найма
это запрещённая практика по AI Act, а не просто рискованная. Не принимает решение по
кандидату. Не выдаёт оценку языка и манеры, если речи было слишком мало, чтобы её обосновать —
вместо буквы уровня в карточке пишется, почему данных не хватило.
